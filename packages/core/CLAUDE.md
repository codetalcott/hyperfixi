# CLAUDE.md - Core Package

This file provides guidance for working with the `@hyperfixi/core` package.

## Package Purpose

Since 4.0, `@hyperfixi/core` is **`@hyperfixi/engine`, re-exported, plus the tooling around it**.
Core's own engine (parser, runtime, ~58 command classes, expressions, registry) was deleted in
Phase C6 of the engine cutover. **Engine work happens in `packages/engine`** — read its README
before changing hyperscript behavior.

What lives here:

```
src/
├── index.ts            # `export * from '@hyperfixi/engine'` + VERSION (ESM only)
├── multilingual/       # /multilingual: parse, render, translate over @lokascript/semantic
├── ast-utils/          # /ast-utils: analysis, interchange AST, withEnginePositions, LSP helpers
├── reference/          # /reference: the engine's commands, syntax, examples
├── lsp-metadata.ts     # /lsp-metadata: keyword lists + hover docs for editors
├── metadata.ts         # /metadata: package + bundle facts
└── version.ts          # GENERATED by scripts/set-version.cjs
browser-tests/          # the Playwright suite (the engine's bundle, the gallery, other packages' pages)
scripts/                # copy-engine-bundle, verify-reference-data, bundle-size-snapshot, …
```

`dist/hyperfixi.js` (`@hyperfixi/core/browser`) is the engine's `hyperfixi-hs.js`, copied by
`scripts/copy-engine-bundle.mjs` — build the engine first.

## Essential Commands

```bash
npm run build --prefix packages/core            # rollup (root + subpaths) + declarations
npm run build:browser --prefix packages/core    # dist/hyperfixi.js from the engine's dist
npm test --prefix packages/core                 # vitest: ast-utils, multilingual, charset, version
npm run typecheck --prefix packages/core
npm run verify:reference --prefix packages/core # reference + LSP data against the engine's grammar

# Browser suite (Playwright) — run from packages/core
cd packages/core && npx playwright test --project=quick --project=comprehensive
cd packages/core && npx playwright test browser-tests/bundle-compatibility.spec.ts
```

## Rules

- **The root re-exports the engine and must not inline it.** `rollup.config.mjs` keeps
  `@hyperfixi/engine` external; an inlined copy is a second engine with its own grammar beside
  the one users `register` into. `scripts/check-node-import.mjs` asserts the root's `register`
  and `api` are the engine's own objects. The root is ESM only because the engine ships no
  CommonJS entry; the subpaths keep their `.cjs` builds.
- **`@lokascript/semantic` is reached only through `await import()` in `/multilingual`**, and the
  root must not import `@lokascript/*` at all (`scripts/check-semantic-boundary.cjs`, a ratchet).
- **The reference and LSP data document the engine.** Adding or changing a command is engine
  work; then update `src/reference/index.ts` and `src/lsp-metadata.ts` and run
  `npm run verify:reference`, which fails on a keyword the engine lacks, a missing entry, an
  example that does not parse on the engine, or a stale count in `metadata.ts`.
- **Examples are upstream's spelling.** Every example here parses on the engine; core-only forms
  (`copy`, `prepend`, `push url`, `.debounce(300)`, `has`, …) were dropped in 4.0.

## Browser Bundles

| Bundle         | Size (gzip) | Use Case                                                                   |
| -------------- | ----------- | -------------------------------------------------------------------------- |
| `hyperfixi.js` | ~34 KB      | The engine's `hyperfixi-hs.js`, copied by `scripts/copy-engine-bundle.mjs` |

Core's own prebuilts retired across Phase C3 (`hyperfixi-hx*.js`, `hyperfixi-hybrid-complete.js`,
`hyperfixi-multilingual.js`, `classic-i18n`, `modular`, and the `lite` / `lite-plus` / `minimal` /
`standard` names) and the `lokascript-*.js` / `hyperfixi-browser.js` alias copies in 4.0. Vite
projects use `@hyperfixi/vite-plugin`; non-English hyperscript runs on `hyperfixi.js` with
`@lokascript/hyperscript-adapter`.
