WebSocket — hx-ws:connect / hx-ws:send

Real htmx 4 with its hx-ws extension, loaded beside hyperfixi-hs.js. The form's hx-ws:send sends its fields as JSON over the socket that hx-ws:connect opened. An incoming JSON message with content, target and swap is swapped where it says; here the mock echoes each message back in that shape.

What's happening

  1. hx-ws sees hx-ws:connect="wss://example/echo" and opens a WebSocket; the form's hx-ws:send sends its fields as JSON ({"headers": {…}, "msg": "…"}) on submit.
  2. The mock echoes {"target": "#messages", "swap": "beforeend", "content": "<div>…"}; htmx swaps the content where the message says. A plain-HTML message uses the connection element's hx-target / hx-swap instead.
  3. A hyperscript handler on the engine can react to the socket's lifecycle (_="on htmx:ws:after:message:incoming …") without touching the transport.
